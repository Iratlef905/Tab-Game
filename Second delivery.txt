Order register
Register a player and associate one with him password. If the player is already registered with a password different then the function returns one error. Otherwise it happens.

The function register it requires 2 arguments:

nick- the player identifier
passwordwhich he chose
This function should be used not only as initial user registration but also as a form of verification at the beginning of the session.

Errors are returned if:

arguments are omitted or not strings
the nick already registered with one password different
Order join
This function pairs 2 players who intend to play a game with one certain board size. If there's a player waiting for a game with the same characteristics then is paired from immediate. Otherwise, the player is registered for one subsequent pairing. In either case, the function returns from immediate. The pairing notification is sent by update. The function join it needs 4 arguments:

group - id do group (debugging)
nick- the player identifier
passwordwhich he chose
size- dimension of the board
Errors are returned if:

some argument is omitted
arguments contain invalid values
authentication does not match a registered player
Order leave
Function invoked to abandon the game. If it is invoked during the pairing, while waiting for other player, then has no consequences. If the game is already in progress, output with this method grant victory to the opponent.

Also note that the games have a timeout 2 Minutes. If a move is not made in due time then one is executed leave automatic, under the conditions described in the preceding paragraph.

The arguments of this function are:

nick- player identification
passwordwhich he chose
game- game identifier
Errors are returned if:

some argument is omitted
authentication does not match a registered player
the game identifier is invalid.

nick- the player identifier

Errors are reported if:

some argument is omitted
arguments contain invalid values
authentication does not match a registered player
try to throw it away at the time
the move violates the rules of the game

nick- the player identifier

Errors are reported if:

arguments contain invalid values

try to pass it away for good
valid plays exist

Function update
This is the only function that uses the method GET, the only supported method by Server Sent Events. The arguments of this function are encoded in urlencoded and are:

game- game identifier
nick- player identifier
At the end of each i throw the object EventSource must be closed

An error will be generated in the request GET if the game reference is invalid.
Ranking
Returns a leaderboard with a maximum of 10 players sorted in descending order of number of wins. Are maintained separate classification tables for each group. The arguments are:

group- group number
size- size of the board
Errors are returned if:

some argument is omitted
arguments contain invalid values

nick
String to identify the player, used in the register and in all functions that require authentication.
password
String used in conjunction with the nick when it is necessary to authenticate the player.
size
Positive integer representing the number of columns the board.

The number squares on the board is quadruple this value.
game
String identifying the game generated by the function join. It's an hash built from game features.
cell
Entire indicated a board house as part of the player's movement.

This house depends step:

step == "from"- house with piece to move
step == "to"- destination house of the piece
When step == "to", the house can be the same indicated in the previous step ("from"). In this case it is annulled the selection of the piece, returned to be in the step from, thus, you can select another piece.
group
Positive integer identifying the group, to avoid pairing with games of colleagues during the development phase. Suggested a use of the group number assigned on the first delivery (see agenda).

This argument is intended to facilitate the debugging. As the server will be shared by all students and there may be several groups to be tested simultaneously, this way it is guaranteed that there is no unexpected pairings.

Different classification tables are also maintained for the different groups.

selected
Array with integers, the positions of the houses involved in the last modification and that can be highlighted on the board.

Positions are indices in the array of pieces, of parts given by property pieces, where position 0 belongs to the player indicated by property initial.

Selected positions are usually the starting and final position of the busy piece. If it is necessary to choose a final position, the selected positions are valid options.
step
One string representing the next step during the moving phase of the pieces. Can have a 3 values:

from- choose the house with the piece to move
tochoose the house where the piece is moved
take- choose the opponent's piece to capture
These choices apply to the player with the turn (turn).
turn
String identifying the player (nick) with the turn to play. Immediately, only plays by this player will be accepted for this game.
winner
String identifying the player (nick) who won this game.

Could be null if the game is over without a winner. This could it also happens if the player leaves while waiting for one adversary.

Once the game has started, if a player abandons it then grants the victory to the opponent.
